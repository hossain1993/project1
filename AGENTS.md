# Project instructions

Read HANDOFF.md and README.md first.

- Treat each folder under sites/ as an independent application. Preserve their distinct designs and existing npm lockfiles.
- All businesses, prices, and booking/order flows are fictional portfolio demonstrations. Keep demo labels visible. Never fabricate testimonials, client commissions, credentials, or registered trademarks.
- Forms must not send or persist personal information, book appointments, or take payments without a new explicit request.
- Retain the existing Sites project IDs. Never initialize replacement Sites for these projects.
- Before claiming a site is published, use authorized Sites publishing tools and verify deployment success. Committing to GitHub alone does not deploy.
- Run the changed site’s production build and TypeScript check. Do not claim browser testing unless actually performed.
- Existing unused scaffold components may fail repository-wide lint. Do not rewrite unrelated vendored components merely to clear those warnings.
- Do not add AI-process language to customer-facing marketing unless requested. Do not make false hand-coding or experience claims.
